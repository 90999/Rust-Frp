把内网服务安全地带到公网

Nfrp 是 fatedier/frp 的 Rust 重实现，完整兼容官方 line protocol v1 与 v2。 官方 frpc / frps 不需要改任何配置就能连上，而服务端常驻内存只有单个数字兆字节。

为什么用它

零配置互通

与官方 frps / frpc 0.71.0 实测互通。默认走 v1，与服务端默认值一致，官方客户端不用改一个字段就能连上。

内存占用低一个数量级

同负载下 Go 版 frps 为 28.8~31.8 MB，Nfrp 约 3.5 MB。单文件部署，无运行时依赖。

按安全产品的标准做

十轮安全审计、140 项修复、每项都带回归测试与退回验证。ACL 覆盖全部数据面入口。

八种代理类型齐全

tcp / udp / http / https / tcpmux / stcp / sudp / xtcp，与官方清单完全一致，含 UDP 打洞直连。

也能当库用

nfrp-common 已发布到 crates.io。只想要协议解析、配置读写、加密实现时，不必跑整个穿透服务。

四种传输层

TCP、KCP、QUIC、WebSocket，外加 TLS 封装。弱网可以用 KCP，被墙可以用 WebSocket。

安装

三种方式，按你的场景选。

方式一：下载预编译二进制

从 Releases 取对应平台的包：

平台文件说明
Windows amd64nfrp-windows-amd64.zipfrps.exe / frpc.exe
Linux amd64nfrp-linux-amd64.tar.gz动态链接 glibc
Linux arm64nfrp-linux-arm64.tar.gz全静态，无 glibc 依赖
Androidnfrp-android-v0.6.1.zipaarch64 + x86_64
源码nfrp-src-v0.6.1.tar.gz完整源码快照

方式二：通过 crates.io

已装 Rust 工具链的话最省事：

cargo install nfrp-server nfrp-client
版本号是分开的

crates.io 上的版本与本页 Release 的版本相互独立。比如 Release 是 v0.6.1 而 crates.io 上可能是 0.6.2 —— 因为 crates.io 不允许重发同一版本号，连修个 README 也得升版本。功能以 Release 为准。

方式三：从源码构建

git clone https://github.com/Nu0vo1212/Rust-Frp
cd Rust-Frp
cargo build --release
# 产物在 target/release/ 下

验证安装

nfrp-server -V     # nfrp-server 0.6.1
nfrp-server -v     # 0.71.0    ← 输出 frp 协议版本，便于按版本号判断的客户端/面板识别
nfrp-client -V     # nfrp-client 0.6.1
-v 为什么输出 0.71.0

这是刻意的。很多管理面板会读 -v 判断对端版本，输出成 0.71.0 才会被当成"正常的 frp"对待。要看 Nfrp 自己的版本用 -V。

快速开始

两分钟跑通一条隧道：把内网的 SSH 服务暴露到公网。

第一步：在公网服务器上启动 frps

cat > frps.toml <<'EOF'
bind_addr = "0.0.0.0"
bind_port = 7000

[auth]
token = "换成你自己的长口令"
EOF

nfrp-server -c frps.toml
一定要配 auth.token

不配 token 又绑在对外地址上，服务端会拒绝启动 —— 因为那等于对外开放一个无认证的穿透节点。这是刻意的。

第二步：在内网机器上启动 frpc

cat > frpc.toml <<'EOF'
server_addr = "你的服务器 IP"
server_port = 7000

[auth]
token = "与上面一致的口令"

[[proxies]]
name = "ssh"
type = "tcp"
local_ip = "127.0.0.1"
local_port = 22
remote_port = 6000
EOF

nfrp-client -c frpc.toml

第三步：连

ssh -p 6000 你的用户名@你的服务器IP

流量路径是：你的终端 → 服务器 6000 端口 → 加密隧道 → 内网机器的 22 端口。

如果用的是官方 frpc

什么都不用改。Nfrp 的 frps 默认走 v1，与官方默认值一致，官方 frpc 直接连就行：

# 官方 frpc 直接指向 nfrp-server 的端口即可
./frpc -c frpc.toml
